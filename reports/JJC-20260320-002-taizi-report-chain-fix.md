# JJC-20260320-002 · 主动回奏链路修复

## 一、问题定义
现有流程中，省部虽有新进展，但“完成后显式唤醒太子回奏皇上”的机制不固定，导致：
- 结果可能停留在中书省/尚书省内部
- 皇上需要手动追问
- 看板虽有进展，但主动回奏链不稳定

## 二、根因
1. **主链缺固定动作**：中书省完结步骤只写了 done / 回奏，没有把“唤醒太子”写成强制动作。
2. **会话绑定不明确**：只有把消息送进太子当前承接皇上的 delivery-bound 会话，太子才天然能在原对话回奏；否则容易变成内部会话自说自话。
3. **无兜底扫描**：任务 done 后若未出现 `太子 -> 皇上` 的流转，没有统一扫描提醒机制。

## 三、实际修改项
### 1. 中书省主链修复
- 文件：`agents/zhongshu/SOUL.md`
- 调整：
  - 将“步骤 4”从“回奏皇上”改为“显式唤醒太子回奏”
  - 明确要求：
    1. 先 `done`
    2. 再 `flow 中书省 -> 太子`
    3. 优先找到太子当前 delivery-bound 会话（如 `agent:taizi:feishu:direct:*`）
    4. 用 `sessions_send` 发 `📮 中书省·请代回奏`
    5. 找不到该会话时，才允许 `agent_dispatch.py taizi` 兜底唤醒

### 2. 太子回奏规则修复
- 文件：`agents/taizi/SOUL.md`
- 调整：
  - 将“收到尚书省最终回奏”扩展为“收到中书省/尚书省的显式回奏唤醒”
  - 明确识别：
    - `📮 中书省·请代回奏`
    - `📮 尚书省·请代回奏`
    - `🔔 待回奏提醒`
  - 明确要求：
    - 正式回奏必须在皇上原对话中进行
    - 回奏字段必须包含：任务ID、结果、证据路径、阻塞项、建议记忆项
    - 收到提醒时，只能核对/提醒，不得把提醒文本直接当正式回奏

### 3. 太子提醒兜底脚本
- 文件：`scripts/list_pending_taizi_reports.py`
- 作用：
  - 扫描 `tasks_source.json`
  - 找出“已完成/已到太子但未见 `太子 -> 皇上` 流转”的任务
  - 默认输出 pending 清单
  - `--reminder` 输出仅提醒太子的消息模板

## 四、兜底机制边界
- 兜底机制**只提醒太子**，不直接替太子向皇上发正式结果
- 正式回奏权仍归太子
- 六部/尚书省不得越级向皇上发正式结果

## 五、联调验证口径
至少覆盖一次：
1. 省部完成
2. 显式唤醒太子
3. 太子在皇上原对话回奏
4. 看板出现 `太子 -> 皇上` 流转

## 六、预期结论
若联调通过，则可认定：
- “有新进展但皇上未收到主动回奏”的主问题已修复
- 皇上不再需要手动追问才能拿到正式结果
- 看板完成态提醒仅作为兜底，不再承担主链职责
