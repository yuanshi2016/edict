# test_framework

在需要规划测试策略、补测试框架、提高回归质量时使用本技能。

## 适用场景

- 新项目建立测试体系
- 老项目补齐测试结构
- 设计 CI 中的自动化测试流程
- 识别测试盲区与高风险模块

## 设计步骤

1. 识别系统边界
   - 核心业务逻辑
   - 外部依赖
   - 高风险模块
2. 设计测试分层
   - 单元测试：验证纯逻辑与边界条件
   - 集成测试：验证模块协作、数据库、缓存、消息队列
   - 端到端测试：验证关键用户路径
3. 设计测试数据策略
   - 固定 fixture
   - 工厂方法
   - 随机数据边界
   - 清理与隔离
4. 设计 CI 策略
   - PR 必跑测试
   - 主干回归测试
   - 覆盖率门槛
   - 失败告警
5. 识别非功能测试
   - 性能基线
   - 安全回归
   - 幂等性
   - 并发场景

## 输出格式

### 测试架构建议
- 测试层级
- 推荐工具
- 目录结构建议

### 优先测试清单
- 先测哪些模块
- 每类测试覆盖什么问题

### CI / 质量门禁
- 哪些检查必须过
- 失败时如何定位

### 风险与盲区
- 当前最容易漏测的地方
- 建议补的测试用例类型

## 原则

- 不追求虚高覆盖率，要追求有效覆盖
- 高风险路径优先
- 测试要稳定、可重复、可维护
- 输出要能直接拿去实施
