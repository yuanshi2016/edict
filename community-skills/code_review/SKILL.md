# code_review

在需要审查代码、PR、设计实现质量时使用本技能。

## 适用场景

- 审查单个文件、模块或完整 PR
- 排查明显 bug、边界条件遗漏、异常处理缺失
- 检查安全问题、性能热点、可维护性问题
- 在上线前给出风险清单和修改建议

## 审查顺序

1. 先理解目标：这段代码要解决什么问题、输入输出是什么
2. 再看正确性：是否存在逻辑错误、空值问题、状态不一致、资源泄漏
3. 再看安全性：鉴权、注入、路径遍历、敏感信息泄漏、权限绕过
4. 再看性能：重复查询、无界循环、大对象复制、阻塞 I/O
5. 再看可维护性：命名、结构、重复代码、耦合度、测试覆盖
6. 最后给出按优先级排序的建议

## 输出格式

### 总结
- 一句话说明整体质量
- 风险等级：高 / 中 / 低

### 发现的问题
按严重级别列出：
- `严重`：会导致错误结果、崩溃、安全漏洞、数据损坏
- `重要`：明显影响稳定性、扩展性、性能
- `建议`：风格、可读性、轻微优化

每个问题都要包含：
- 位置（文件 / 函数 / 代码段）
- 问题描述
- 影响
- 修改建议

### 建议修复顺序
1. 先修严重问题
2. 再补测试
3. 再做结构优化

## 注意事项

- 不要只说“代码不错”这类空话
- 没把握的地方要明确写出假设
- 如果信息不足，先指出缺失的上下文
- 如果代码已经足够好，也要说明“为什么好”
